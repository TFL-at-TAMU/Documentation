## 4. The Starlight migration (DONE)

**Status: executed and live** — Phases 1–3 of **[STARLIGHT_MIGRATION.md](STARLIGHT_MIGRATION.md)** completed 2026-07-16/17 (PR #30 + Cloudflare cutover). Content moved with `git mv` (history preserved); cross-links slugified; duplicate H1s deduped; binaries under `/files/`; staff trees excluded from the build. Remaining Phase 4 cleanup is tracked in `TODO.md`. Historical notes below.

- **Why:** Docsify renders in-browser (weak SEO, hijacks shared elements — it grabbed the top bar's `<nav>` and abs-positioned it; bakes theme colors so the toggle needs a reload; no build-time validation of broken links). Starlight = static HTML at build, autogenerated sidebar (retires `generate_sidebar.py`), Pagefind search, custom pages for the landing, and is Cloudflare-backed (Cloudflare acquired Astro Jan 2026 — same platform we host on).
- **Proof-of-concept:** branch **`poc/starlight`** (pushed to origin). Astro **7.0.6** + Starlight **0.41.3**, pinned. Builds 73 pages clean; reviewed and approved. It's a reference — the real migration re-does the work with `git mv`.
- **Contact page spec** (owner-approved): a `/contact/` page with a prominent **Discord button** (`https://discord.gg/Tvn9rsBUWH`) + people cards — **Jimmy Walker (President), Aidan Stewart (Vice President), Paul Deere (Sponsoring Professor)** — with visible placeholders for unknown contact details.
- **⚠️ New-machine prerequisite:** **Node.js is not yet installed on the new laptop.** Starlight needs it (v20+; v24 LTS was used). Install before any migration work: `winget install OpenJS.NodeJS.LTS` (Windows), then a fresh shell.
- **Sidebar gotcha (cost us a debugging round):** Starlight `autogenerate.directory` matches the **on-disk folder path** (`docs/CNC Mill`), NOT the slugified route (`docs/cnc-mill`). Slugified paths silently build empty sidebar groups.

## 7. Working preferences & hard-won lessons

- **Delegation model the owner likes:** the main/supervisor session reviews and decides; bulk coding is delegated to **cheaper-model subagents (Sonnet)** via the Agent tool with `isolation: worktree`, local commits only — supervisor reviews, pushes, and merges. (Token savings.)
- **Demand *behavioral* verification from subagents, not existence checks.** A PoC agent verified sidebar *labels* existed but not that groups had *children* (they were empty) — the bug shipped to review. Briefs must ask for counts/curl of actual behavior; the supervisor re-verifies independently.
- **Browser caching masked correct fixes at least twice** in this project (both the shared-JS fix and a rebuild). When verifying web output: check the built file on disk first, then hard-refresh (Ctrl+Shift+R) / cache-bust the URL. This is also why `_headers` exists.
- **For subjective/aesthetic CSS**, the owner prefers to hand-tweak the file themselves before you commit — offer to pause and point them at the file + local preview rather than iterating via commits.
- **Deploy-coordination gotcha:** repo layout changes and Cloudflare build settings must change together; if they diverge the production build fails, but Cloudflare keeps serving the last good deploy so the site doesn't go down.
- The site is **barely used right now**, so brief downtime during the migration cutover is acceptable — don't over-engineer coordination.
